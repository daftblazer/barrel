# Ryza parity scoreboard

Each row is a scenario. Its game capture comes from `../ryza-recomp/scenarios/<name>.sh`
(`tools/scenario.sh` there, on a 1920 × 1080 headless display), Barrel's trace from the matching
Barrel run, diffed with `barrel-parity` (docs/parity.md). Textures are named through
`../ryza-recomp/work/traces/textures.tsv`. Mismatches count the diff's lines, game frame
against Barrel frame.

The captures are made on ryza-recomp's exact virtual clock and repeat frame for frame, so a
row's time is `(frame - start) / 60` with nothing fitted. Frame numbers in the other docs that
come from the first capture (the title at 1140, the notice at 278, the 3D frame 1400) are 265
higher than this one's (875, 11 after its two-frame earlier notice, 1135).

**gather**: three kinds of row. The draws and the item run `barrel-tool ryza-gather` from the game's
generator window at 2040 (ryza-recomp `dumps/2040.1.bin`) and diff its calls with the hook log's lines
of frame 2041 (integers are hex there); the cues run the offscreen replay (`--gather NEAR:PRESS`: the
frames the prompt came up and A went down, her place and turn at the stop) with the cue trace
(`BARREL_TRACE_CUES`, frames counted as the capture's) against the hook log's `play` lines; the UI rows
diff one captured frame each and count only the quads whose texture is one of the game's `res_*` files
(`grep -E '^  (GAME|BARREL) .*res_'` over the diff), because the gathering's effect sprites are the
particles' textures and are not drawn. `--hud-arrival` is 1730 here, two frames later than `hud-walk`'s
1728: the destination glow's loop (71 frames, started 2 before the arrival) fits the capture with it.
